Handoff développement · 46 écrans

Spécification de build

Inventaire complet des écrans OXV à implémenter en React Native. Chaque écran HTML livré est une référence visuelle ; ce document donne pour chacun sa cible .tsx, son archétype, le chiffre roi, les données à brancher, la traduction data-viz vers Skia, la navigation et les états. Les tokens, fonts et la doctrine sont dans le GUIDE_INTEGRATION ; ne pas les redéfinir ici.

0 · Socle technique

Stack

Expo (React Native) · expo-router (routes = arborescence fichiers) · @shopify/react-native-skia (toute la data-viz) · react-native-reanimated (animations) · react-native-gesture-handler (pinch/pan/scrub) · expo-font (Rajdhani, JetBrains Mono, Instrument Serif).

Conventions

1 écran = 1 route .tsx. Préfixe fichier = espace (app/ coach/ partenaire/ admin/). Composants partagés dans components/. Rendu = pur affichage ; données via hooks/store. Animations non bloquantes (état au repos = valeur finale).

Archétypes (gabarits réutilisables) : A1 hub d'accueil · A2 instrument+détail · A3 index de vues · A4 canvas plein cadre · A5 profil/trace · A6 comparateur A/B · A8 formulaire · A9 liste/annuaire · A11 annotation/action coach.

Composants partagés à créer d'abord : <AppBar> · <CockpitPanel> (corner brackets) · <KingNumber> (grand chiffre or) · <MeterBar> · <QdiRadar> (Skia) · <SpeedTrace> (Skia) · <StatusPill> · <RoleBadge> · <CoachBand> (rouge) · <StateWrapper> (nominal/vide/chargement/hors-ligne/erreur).

5 · États & doctrine à repasser sur chaque écran data

5 états obligatoires
  • Nominal — données réelles.
  • Vide — EmptyState doux, jamais culpabilisant.
  • Chargement — squelette calme (jamais spinner nu).
  • Hors-ligne — dernière lecture datée + reconnexion.
  • Erreur — cause + action de reprise.
Checklist doctrine
  • Or = donnée · un seul chiffre roi/écran.
  • Couleur d'identité par rôle (jamais l'or).
  • Bande coach rouge séparée du miroir.
  • Piliers/phases : palette fixe (voir guide).
  • Références self-only, méthode/transparence visible.
  • Animations non bloquantes (Reanimated).
Ordre de build conseillé

① Composants partagés + tokens/fonts → ② Espace Pilote (le miroir, base de tout) → ③ Espace Coach (workflow séance : contexte→facturation→triage→studio→plan→rapport) → ④ Partenaire → ⑤ Admin. Les écrans HTML de référence sont dans le projet, un par ligne des tables ci-dessus (app__ / coach__ / partenaire__ / admin__).
